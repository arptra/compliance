# Как пользоваться DeepSeek SDD обычному пользователю

Этот файл для ситуации, когда вы не хотите разбираться в разработке, Gradle,
тестах, SDD и внутренней структуре проекта.

## Самая короткая команда

Откройте DeepSeek CLI в корне Java/Gradle проекта и напишите:

```text
Прочитай файл `/path/to/prompts/deepseek-sdd-sot/START_HERE.md`, выполни его инструкции для текущей Java/Gradle-репы и веди меня через меню. Я не разработчик: задавай вопросы по одному, проси отвечать цифрами и не перечитывай весь проект без необходимости.
```

Замените `/path/to/prompts/deepseek-sdd-sot/START_HERE.md` на настоящий путь к
файлу `START_HERE.md`.

## Первый запуск в новом проекте

1. Вы открываете терминал в корне Java проекта.
2. Запускаете DeepSeek CLI.
3. Вставляете короткую команду выше.
4. DeepSeek сам проверяет проект.
5. Если проект еще не подготовлен, он покажет меню:

```text
1. Initialize the repo for guided feature development.
2. Only inspect and explain what is missing.
3. Stop.
```

6. Вы отвечаете `1`.
7. DeepSeek спросит подтверждение `YES` или `NO`.
8. Вы отвечаете `YES`.
9. Он создает служебные файлы:
   - карту проекта
   - короткие context packs
   - шаблоны задач
   - хранилище известных ошибок
   - правила для будущих сессий

На первом запуске production Java код не должен меняться.

## Последующая работа с новой фичей

Каждый раз начинайте так же:

```text
Прочитай файл `/path/to/prompts/deepseek-sdd-sot/START_HERE.md`, выполни его инструкции для текущей Java/Gradle-репы и веди меня через меню. Я не разработчик: задавай вопросы по одному, проси отвечать цифрами и не перечитывай весь проект без необходимости.
```

Если проект уже подготовлен, DeepSeek покажет меню:

```text
1. Create a new feature spec.
2. Create a feature spec and then implement it after approval.
3. Continue an existing feature/task.
4. Fix a failing test/build/error using the error memory first.
5. Refresh repository context.
```

Обычно выбирайте:

- `1`, если нужно сначала спокойно описать фичу и ничего не кодить.
- `2`, если хотите, чтобы он сначала написал план, потом спросил разрешение и
  начал реализацию.
- `3`, если фича уже была начата и нужно продолжить.
- `4`, если что-то упало с ошибкой.
- `5`, если проект сильно изменился и нужно обновить короткое описание проекта.

## Минимальный сценарий для новой фичи

1. Вставьте стартовую команду.
2. Выберите `2`.
3. Когда DeepSeek спросит описание, напишите одну фразу:

```text
Нужно добавить экспорт отчета в Excel с фильтрами по дате и статусу.
```

4. DeepSeek создаст spec и список задач.
5. Он спросит, можно ли начинать реализацию.
6. Ответьте `YES`.
7. После реализации он должен запустить Gradle unit tests.
8. Если тесты упали, он должен починить проблему или объяснить, почему она не
   относится к текущей фиче.

## Как работает память ошибок

В проекте создается папка:

```text
.ai/error-kb/
```

Туда DeepSeek записывает типовые ошибки и проверенные решения.

Когда ошибка встречается снова:

1. DeepSeek сначала смотрит `.ai/error-kb/index.yml`.
2. Если похожая ошибка уже была, берет готовое решение.
3. Если ошибки еще не было, чинит ее.
4. После успешного исправления записывает решение в `.ai/error-kb/`.

Эту папку можно коммитить и передавать другим через git.

## Что писать DeepSeek, если он начал умничать

```text
Стоп. Вернись к меню из START_HERE.md. Я хочу отвечать цифрами и короткими фразами. Не читай весь проект заново, используй context-map, context-packs, active spec и error-kb.
```

## Что писать, если нужно продолжить после перезапуска CLI

```text
Прочитай START_HERE.md и восстанови сессию по файлам проекта. Не перечитывай весь проект. Покажи меню и спроси, что делать дальше.
```

## Что писать, если тесты упали

```text
Сначала проверь `.ai/error-kb`, есть ли известное решение этой ошибки. Если нет, исправь ошибку, запусти Gradle unit tests и запиши найденное решение в `.ai/error-kb`.
```
